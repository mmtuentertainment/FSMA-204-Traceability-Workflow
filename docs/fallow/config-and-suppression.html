Config & suppression

The .fallowrc.jsonc schema and the inline-suppression tokens. Golden rule from fallow: prefer the narrowest mechanism that matches the reason, and document why next to it. See this repo's actual config on This project.

Config file forms. .fallowrc.json, .fallowrc.jsonc (comments allowed — preferred so exceptions carry their reason), or fallow.toml. Add "$schema": "https://raw.githubusercontent.com/fallow-rs/fallow/main/schema.json" for editor autocomplete. fallow needs zero config for most repos (118 auto-detecting plugins) — only add a key when a real false positive or policy choice requires it.

Inline suppression #

Comment forms. The token must match the analysis — this is the #1 mistake.

// fallow-ignore-next-line <token>     // suppress the next line
// fallow-ignore-file <token>          // suppress the whole file (top of file)
<!-- fallow-ignore-file complexity -->   // HTML/templates (no line comments)

Token table #

AnalysisToken(s)Example
Dead codeunused-export, unused-file, unused-type, unused-dependency, type-only-dependency, test-only-dependency, circular-dependency, boundary-violation, …// fallow-ignore-next-line unused-export
Duplicationcode-duplication (NOT a dead-code token)// fallow-ignore-next-line code-duplication
Complexitycomplexity// fallow-ignore-next-line complexity
Securitysecurity-sink// fallow-ignore-file security-sink
Stale suppressions are detected. A fallow-ignore comment that no longer matches any issue is reported (stale-suppressions, default warn) — so dead suppressions can't silently hide regressions. Remove them when flagged.

JSDoc visibility tags #

Block comments only (/** */) — line comments are ignored. Keep an export alive without an ignore:

TagMeaning
/** @public */ / /** @api public */Public API consumed externally — never unused.
/** @internal */ · /** @beta */ · /** @alpha */Kept-alive visibility annotations.
/** @expected-unused */Intentionally unused — but fallow warns if it becomes used (stale). Prefer this over a plain ignore when you want that signal.

Preference order (narrow → broad) #

  1. Inline // fallow-ignore-next-line (one line) / JSDoc tag
  2. ignoreExports (one export) / ignoreDependencies (one dep)
  3. dynamicallyLoaded / publicPackages / ignoreDecorators (a class of cases)
  4. overrides (a directory/pattern rule adjustment)
  5. ignorePatterns (whole files out of scope — generated only) — last resort
